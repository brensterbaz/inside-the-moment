## Challenge intent

Microsoft and the Premier League seek an AI application or agent that turns synthetic football events into understandable match analysis, timely narratives, automatic recaps and personalised audience experiences. Target uses include fans, studios, broadcast and streaming. The challenge's tagline describes an insights engine running on Azure.

A project may be an agent, workflow, integration, analytics/data platform, automation or a new experience. It should respond quickly enough for live play and explain the significance of action rather than merely list statistics.

Synthetic, football-realistic data is required. Participants are not supplied with real Premier League match data.

## Five-stage pipeline

| Stage | Expected capability |
| --- | --- |
| Ingest | Process synthetic events over time: passes, shots, tackles, possession, pressure and match metadata. |
| Interpret | Convert events into meaningful statistics, patterns and contextual match state. |
| Explain | Describe why a moment matters, using the available evidence. |
| Render | Present useful insights alongside the match experience. |
| Personalise | Deliver materially different experiences for casual fans and analysts; preferences may include club, player, language or metric. |

The brief permits emphasis on synchronised, machine-readable overlays or on audience-specific experiences, or both. Analysis still needs an audience-facing presentation, and personalisation needs meaningful intelligence underneath it.

## Detailed capability areas

- **Real-time intelligence:** aggregate incoming events into football states and statistics. Suggested features include player name tags; optional threshold-triggered speed/distance indicators; pass distance, accuracy and difficulty; and ball/shot speed.
- **Auto-eventing:** model-based detection of passes and speed from incoming video is a feature to consider. It is not presented as a compulsory computer-vision subsystem for every entry.
- **Narrative generation:** identify key stories, player performance context, milestones and match recaps.
- **Explainability:** show why an event matters in context, for example pressure changes, control/chaos or shifts in match rhythm.
- **Data innovation:** create or extend plausible synthetic football datasets, including action events and match metadata.
- **Multiple languages:** produce natural-language storytelling capable of serving studio/streaming audiences in more than one language.

Examples such as favourite-player mode are options, not an instruction to implement every possible personalisation feature. The five stages, explainability and audience adaptation should be demonstrable in the final experience.

## What to submit

- A new project meeting the challenge requirements.
- A short pitch explaining the problem, solution, behaviour and Microsoft/Azure technologies actually used.
- A demonstration video shorter than two minutes, showing the app functioning on its intended device/platform.
- A public video URL on YouTube, Vimeo, Facebook Video or Youku, included on the project page.
- A public GitHub repository URL.
- Permission for any third-party trademarks, music or other protected material included in the video.

The public official rules also cover working-project access, hardware testing, eligibility and legal conditions; see [HACKATHON.md](../HACKATHON.md).

## Judging rubric

Each area has a **20% weighting**.

| Area | What the portal asks judges to assess |
| --- | --- |
| Technological implementation | Engineering quality, effective use of the featured technologies, documentation and maintainability. |
| Agentic design and innovation | Purposeful agent behaviour/orchestration and useful technical novelty. |
| Real-world impact and applicability | Importance of the problem, usefulness and readiness for deployment. |
| User experience and presentation | Intuitive interaction, a clear demonstration of value, and frontend/backend balance. |
| Adherence to category | Fit with the relevant award category description. |
